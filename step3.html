STEP 3 20분 🎤 진행자가 직접 설명

GitHub + Vercel 배포

이 단계는 AI 프롬프트가 아니라 화면을 따라가는 작업입니다

지금까지 만든 사이트는 내 Replit 안에만 있습니다. 이걸 인터넷 주소가 있는 진짜 웹사이트로 만드는 게 마지막 단계예요. GitHub는 코드를 보관하는 창고, Vercel은 그 창고를 보고 사이트를 띄워주는 서비스입니다. 딱 그만큼만 알면 됩니다.

목표누구나 들어올 수 있는 내 사이트 주소를 갖습니다. 휴대폰으로 열면 오늘 끝.
시간20분 — 진행자가 화면을 공유하고 다 함께 한 단계씩
준비물GitHub 계정(로그인 상태), Vercel 계정은 여기서 GitHub으로 만듭니다
끝나면프로젝트명.vercel.app 주소가 생기고, 앞으로 코드를 고쳐 Push할 때마다 자동으로 갱신됩니다.

지금 무슨 일이 일어나는 건가요

지금까지 만든 파일은 내 Replit 안에만 있습니다. 남에게 보여주려면 두 곳을 거쳐야 해요.

① Replit
내 작업실. 나만 볼 수 있음
→
② GitHub
코드 보관 창고. 여기에 Push로 올림
→
③ Vercel
창고를 보고 사이트로 띄워주는 서비스. 주소가 나옴
✱ 왜 두 단계나 거치나요

GitHub은 보관, Vercel은 공개를 맡습니다. 역할이 나뉘어 있어서 좋은 점이 하나 있어요 — 한 번 연결해두면 그다음부터는 코드를 고쳐 Push하기만 하면 사이트가 저절로 갱신됩니다. 매번 파일을 올릴 필요가 없습니다. 오늘 20분을 쓰는 이유가 이겁니다.

⛔ 시작 전에 하나만 — 권한 승인 팝업

Replit에서 GitHub를 연결할 때, 그리고 Vercel에서 GitHub로 로그인할 때 권한 승인 창이 새 창(팝업)으로 뜹니다. 이게 브라우저 팝업 차단에 막히거나, 뒤쪽 창에 숨어서 안 보이는 경우가 많습니다.

  • "연결이 안 돼요"라고 하면 먼저 다른 창이 열려 있는지 확인해보세요.
  • 주소창 오른쪽 끝에 팝업 차단 아이콘이 있으면 허용으로 바꿉니다.
  • 그래도 안 되면 브라우저를 껐다 켜고 다시 시도하는 게 제일 빠릅니다.

따라 하기

  • 1

    GitHub 저장소 만들기

    github.com 접속 → 오른쪽 위 + → New repository

    • Repository name: 영문 소문자로 (예: book-review-board)
    • 공개 설정: Public — Private으로 하면 무료 배포에서 막힐 수 있습니다
    • 나머지는 건드리지 말고 Create repository
  • 2

    Replit 코드를 GitHub로 내보내기

    Replit 왼쪽의 버전 관리(Git) 아이콘 클릭 → GitHub 계정 연결 → 방금 만든 저장소 선택 → Push

    • 연결할 때 GitHub 권한 승인 팝업이 뜹니다. 반드시 Authorize를 눌러주세요.
    • Push가 끝나면 GitHub 저장소 페이지를 새로고침해서 index.html 같은 파일이 올라왔는지 눈으로 확인합니다.
  • 3

    Vercel 접속 및 로그인

    vercel.com 접속 → Continue with GitHub

    • 이메일로 따로 가입하면 안 됩니다. 반드시 GitHub 계정으로 로그인해야 저장소가 보입니다.
  • 4

    새 프로젝트 만들기

    Add New → Project → 방금 올린 저장소 옆의 Import → 설정은 그대로 두고 Deploy

    • 저장소 목록에 아무것도 안 보이면 Adjust GitHub App Permissions에서 저장소 접근 권한을 열어주세요.
    • 빌드 설정은 손대지 마세요. 순수 HTML 사이트는 기본값으로 그냥 됩니다.
  • 5

    배포 완료 확인

    1~2분 뒤 축하 화면이 뜨고 프로젝트명.vercel.app 주소가 나옵니다. 그 주소를 눌러서 내 사이트가 실제로 열리는지 확인하세요.

    • 휴대폰으로도 열어보세요. 오늘의 하이라이트입니다.
    • 주소를 단톡방에 공유해서 서로 글을 남겨보면 분위기가 확 삽니다.

앞으로 코드를 고치면?

한 번 연결해두면 그다음은 자동입니다. Replit에서 코드를 고치고 다시 Push만 하면, Vercel이 알아서 새 버전을 배포합니다. 따로 할 일이 없어요.

고친 게 사이트에 안 보인다면 순서대로 확인하세요. ① Replit에서 Push를 했는지 → ② GitHub 저장소에 방금 시각이 찍혔는지 → ③ Vercel 대시보드에 새 배포가 도는지. 대개 ①에서 멈춰 있습니다. 배포에는 1~2분 걸리니 조금 기다렸다 새로고침해 보세요.

자주 나오는 질문

주소가 너무 길고 이상해요. 바꿀 수 있나요?

Vercel 프로젝트 Settings → Domains에서 내가정한이름.vercel.app으로 바꿀 수 있습니다. 이미 쓰는 사람이 있는 이름은 안 되니 몇 개 후보를 생각해두세요. 진짜 내 도메인(.com이나 한글 도메인)을 붙이는 방법은 여유 시 도전 과제에 있습니다.

돈이 나가나요?

오늘 범위에서는 전부 무료입니다. Vercel 무료 플랜은 개인 사이트 정도의 방문자는 충분히 감당해요. 돈이 드는 건 도메인을 따로 사는 경우뿐입니다.

Public으로 올리면 코드를 남이 볼 수 있나요?

볼 수 있습니다. 그래서 비밀번호나 개인정보를 코드에 적어두면 안 됩니다. 오늘 만드는 게시판 코드에는 그런 게 없어서 괜찮아요. 참고로 웹사이트 화면 코드(HTML·CSS·JS)는 배포하는 순간 어차피 방문자 브라우저로 전달됩니다.

저장소 목록에 제 프로젝트가 안 보여요

Vercel이 GitHub 저장소를 볼 권한을 못 받은 경우입니다. Import 화면의 Adjust GitHub App Permissions를 눌러 All repositories로 열어주세요. 그래도 없으면 GitHub 저장소에 파일이 실제로 올라갔는지(2번 단계) 먼저 확인합니다.

배포는 됐는데 화면이 하얗게 떠요
  • 저장소 맨 위에 index.html이 있어야 합니다. 폴더 안에 있으면 안 열려요.
  • 파일 이름 대소문자를 확인하세요. Style.css와 style.css는 다른 파일입니다. 내 컴퓨터에서 되던 게 배포 후 깨지는 가장 흔한 원인입니다.
배포한 사이트에서 글쓰기가 안 돼요

배포와 저장은 다른 문제입니다. Apps Script 웹앱 주소가 코드에 제대로 들어가 있는지, 액세스 권한이 모든 사용자인지 확인하세요. STEP 2의 자주 나오는 질문과 에러 해결법을 보시면 됩니다.

🎤 진행자용 — 반드시 다 함께 진행하세요

여기는 프롬프트를 복사하는 구간이 아닙니다. 진행자가 화면을 공유하고 한 단계씩 같이 클릭하세요. 각자 알아서 하게 두면 반드시 흩어집니다.

다 함께 1번을 끝내고 2번으로 넘어가세요. 단계마다 "지금 화면에 Create repository 버튼 보이시는 분?"처럼 눈에 보이는 것으로 확인하면 뒤처진 사람을 놓치지 않습니다.

팝업 차단으로 막히는 사람이 꼭 나옵니다. 위 경고 상자를 시작 전에 미리 읽어주세요. 겪은 뒤에 설명하면 이미 당황한 상태입니다.

STEP 3 20분 🎤 진행자가 직접 설명

GitHub Pages 배포

이 단계는 AI 프롬프트가 아니라 화면을 따라가는 작업입니다

지금까지 만든 사이트는 내 StackBlitz 안에만 있습니다. 이걸 인터넷 주소가 있는 진짜 웹사이트로 만드는 게 마지막 단계예요. GitHub는 코드를 보관하는 창고인데, 같은 GitHub이 그 창고를 그대로 웹사이트로 띄워주는 기능을 함께 갖고 있습니다. 그게 GitHub Pages예요.

목표누구나 들어올 수 있는 내 사이트 주소를 갖습니다. 휴대폰으로 열면 오늘 끝.
끝나면내아이디.github.io/저장소이름/ 주소가 생기고, 앞으로 Commit을 누를 때마다 사이트가 저절로 갱신됩니다.

지금 무슨 일이 일어나는 건가요

지금까지 만든 파일은 내 StackBlitz 안에만 있습니다. 남에게 보여주려면 두 곳을 거쳐야 해요.

① StackBlitz
내 작업실. 나만 볼 수 있음
→
② GitHub
코드 보관 창고. 여기에 Commit으로 올림
→
③ GitHub Pages
그 창고를 그대로 웹사이트로 띄움. 주소가 나옴
✱ 왜 두 단계나 거치나요

사실 두 단계가 아니라 한 곳입니다. GitHub이 보관과 공개를 둘 다 맡아요. 한 번 켜두면 그다음부터는 StackBlitz에서 Commit만 누르면 사이트가 저절로 갱신됩니다. 매번 파일을 올릴 필요가 없어요. 오늘 20분을 쓰는 이유가 이겁니다.

⛔ 시작 전에 하나만 — 권한 승인 팝업

StackBlitz에서 저장소를 만들 때 GitHub 권한 승인 창이 새 창(팝업)으로 뜹니다. 이게 브라우저 팝업 차단에 막히거나, 뒤쪽 창에 숨어서 안 보이는 경우가 많습니다.

  • "연결이 안 돼요"라고 하면 먼저 다른 창이 열려 있는지 확인해보세요.
  • 주소창 오른쪽 끝에 팝업 차단 아이콘이 있으면 허용으로 바꿉니다.
  • 그래도 안 되면 브라우저를 껐다 켜고 다시 시도하는 게 제일 빠릅니다.

따라 하기

저장소는 GitHub이 아니라 StackBlitz에서 만듭니다. 이미 GitHub 계정으로 로그인해 두었으니, 버튼 몇 번이면 끝나요. 누를 곳은 딱 두 군데입니다.

  • 1

    StackBlitz에서 저장소 만들기

    내 프로젝트를 연 상태에서 왼쪽 사이드바(파일 목록이 있는 곳)의 Connect repository를 누릅니다.

    • 저장소 이름을 영문 소문자로 적습니다 (예: book-review)
    • 공개 설정은 Public — 비공개(private)는 StackBlitz 유료 기능입니다
    • 처음이라면 GitHub 권한 승인 팝업이 뜹니다. Authorize를 눌러주세요

    이미 GitHub에 만들어둔 저장소에 연결하고 싶다면, 같은 화면의 기존 저장소 가져오기 링크를 쓰면 됩니다.

  • 2

    Commit을 눌러 GitHub에 올리기

    저장소가 연결되면 화면 위쪽 메뉴바에 Commit 버튼이 생깁니다. 그걸 누르면 지금까지 만든 파일이 GitHub으로 올라갑니다.

    • 메시지를 적으라고 하면 first commit처럼 아무거나 적으면 됩니다
    • 올린 뒤 github.com의 내 저장소를 열어 index.html이 보이는지 눈으로 확인하세요
  • 3

    GitHub Pages 켜기

    방금 만든 저장소 페이지에서 위쪽 Settings → 왼쪽 메뉴 Pages

    • Source: Deploy from a branch
    • Branch: main / 폴더는 / (root)
    • Save

    저장하면 위쪽에 내아이디.github.io/저장소이름/ 주소가 나타납니다.

  • 4

    1~2분 기다렸다가 열어보기

    바로 누르면 404가 뜹니다. 고장이 아니라 아직 준비 중인 거예요. 1~2분 뒤 새로고침하면 내 사이트가 열립니다.

    • 진행 상황은 저장소 위쪽 Actions 탭에서 볼 수 있습니다. 초록 체크가 뜨면 완료입니다.
    • 휴대폰으로도 열어보세요. 오늘의 하이라이트입니다.
    • 주소를 단톡방에 공유해서 서로 글을 남겨보면 분위기가 확 삽니다.
⚠ 저장소 맨 위에 index.html이 있어야 합니다

GitHub Pages는 저장소 맨 바깥에 있는 index.html을 첫 화면으로 씁니다. 이건 정하기 나름이 아니라 웹의 규칙이에요. 다른 파일 이름은 무엇이든 상관없지만, 첫 화면만은 index.html이어야 합니다.

내 목록 화면 파일이 다른 이름이라면 AI에게 "첫 화면 파일 이름을 index.html로 바꾸고, 그걸 부르는 링크도 같이 고쳐줘"라고 하세요. 파일이 폴더 안에 들어가 있어도 안 열립니다. GitHub 저장소를 열었을 때 index.html이 바로 보이면 정상입니다.

앞으로 코드를 고치면?

한 번 켜두면 그다음은 자동입니다. StackBlitz에서 코드를 고치고 Commit만 누르면, GitHub이 알아서 새 버전을 올립니다. 따로 할 일이 없어요.

고친 게 사이트에 안 보인다면 순서대로 확인하세요. ① StackBlitz에서 Commit을 눌렀는지 → ② GitHub 저장소에 방금 시각이 찍혔는지 → ③ 저장소 Actions 탭에 새 작업이 도는지. 대개 ①에서 멈춰 있습니다. 미리보기 화면이 바뀌었다고 배포된 게 아니에요 — Commit을 눌러야 GitHub으로 넘어갑니다. 배포에는 1~2분 걸리니 조금 기다렸다 새로고침해 보세요.

자주 나오는 질문

주소가 너무 길고 이상해요. 바꿀 수 있나요?

주소의 뒷부분은 저장소 이름이라, GitHub에서 저장소 이름을 바꾸면 주소도 바뀝니다(Settings → Repository name). 진짜 내 도메인(.com이나 한글 도메인)을 붙이는 방법은 여유 시 도전 과제에 있습니다.

돈이 나가나요?

오늘 범위에서는 전부 무료입니다. GitHub Pages는 공개 저장소라면 무료이고, 개인 사이트 정도의 방문자는 충분히 감당해요. 돈이 드는 건 도메인을 따로 사는 경우뿐입니다.

Public으로 올리면 코드를 남이 볼 수 있나요?

볼 수 있습니다. 그래서 비밀번호나 개인정보를 코드에 적어두면 안 됩니다. 오늘 만드는 게시판 코드에는 그런 게 없어서 괜찮아요. 참고로 웹사이트 화면 코드(HTML·CSS·JS)는 배포하는 순간 어차피 방문자 브라우저로 전달됩니다.

Settings에 Pages 메뉴가 안 보여요

저장소가 비공개(Private)인 경우입니다. 무료 계정은 공개 저장소에서만 Pages를 쓸 수 있어요. 저장소 Settings → General 맨 아래 Change repository visibility에서 Public으로 바꾸세요. 그래도 없으면 지금 보고 있는 게 내 저장소가 맞는지 확인합니다.

배포는 됐는데 화면이 하얗게 떠요
  • 저장소 맨 위에 index.html이 있어야 합니다. 폴더 안에 있으면 안 열려요.
  • 파일 이름 대소문자를 확인하세요. Style.css와 style.css는 다른 파일입니다. 내 컴퓨터에서 되던 게 배포 후 깨지는 가장 흔한 원인입니다.
배포한 사이트에서 글쓰기가 안 돼요

배포와 저장은 다른 문제입니다. Apps Script 웹앱 주소가 코드에 제대로 들어가 있는지, 액세스 권한이 모든 사용자인지 확인하세요. STEP 2의 자주 나오는 질문과 에러 해결법을 보시면 됩니다.

🎤 진행자용 — 반드시 다 함께 진행하세요

여기는 프롬프트를 복사하는 구간이 아닙니다. 진행자가 화면을 공유하고 한 단계씩 같이 클릭하세요. 각자 알아서 하게 두면 반드시 흩어집니다.

다 함께 1번을 끝내고 2번으로 넘어가세요. 단계마다 "지금 화면에 Create repository 버튼 보이시는 분?"처럼 눈에 보이는 것으로 확인하면 뒤처진 사람을 놓치지 않습니다.

팝업 차단으로 막히는 사람이 꼭 나옵니다. 위 경고 상자를 시작 전에 미리 읽어주세요. 겪은 뒤에 설명하면 이미 당황한 상태입니다.

Pages를 켠 직후 404가 뜨는 것도 미리 말해두세요. "아직 준비 중이라 그렇습니다, 1~2분 뒤에 새로고침하세요" 한마디면 "안 되는데요"가 여섯 번 나오는 걸 막습니다.

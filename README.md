# AnyoneCanCode — 비개발자 웹사이트 워크샵

한 저장소에 **정적 HTML 사이트 2개**가 들어 있습니다. 프레임워크·빌드 도구·백엔드 없이 순수 HTML/CSS/JS로만 되어 있습니다.

| 경로 | 정체 | 성격 |
|---|---|---|
| `/` | 워크샵 진행용 가이드 문서 사이트 | 코드 에디터 톤 (다크 기본 · 라이트 전환 가능) |
| `/sample/` | 참가자에게 보여줄 "완성본 예시" 데모 | 버건디+크림 따뜻한 톤 |

저장소 루트를 그대로 GitHub Pages / Vercel에 올리면 `/`가 가이드, `/sample/`이 데모가 됩니다. 빌드 설정 없음.

> **이 문서의 용도** — 이 저장소를 이어서 작업하는 사람(또는 Claude)이 읽는 사양서 겸 프롬프트입니다. 왜 이렇게 만들었는지와, 고칠 때 깨뜨리면 안 되는 것들을 담았습니다.

## 폴더 구조

```
저장소 루트/
├── index.html          ← 1페이지 · 개요 + 전날 체크리스트 (항상 공개)
├── dday.html           ← 오늘 할 일 (개념·순서·용어, 당일 공개)
├── templates.html      ← 범용 프롬프트 템플릿
├── step1.html          ← 화면(UI) 만들기
├── step2.html          ← Google Sheets 연동
├── step3.html          ← GitHub + Vercel 배포
├── extra.html          ← 여유 시 도전 과제
├── errors.html         ← 에러 해결법
├── tips.html           ← AI와 일하는 두 가지 습관 (심화)
├── style.css           ← 가이드 전용 스타일시트
├── ide.js              ← 가이드 전용 에디터 UI 스크립트 (9개 페이지 공용)
├── README.md           ← 이 파일
└── sample/
    ├── index.html      ← 완성본 데모 메인 (타임라인 목록)
    ├── write.html      ← 후기 쓰기
    ├── detail.html     ← 상세보기
    └── style.css       ← 데모 전용 스타일시트
```

두 사이트의 `style.css`는 **완전히 별개**입니다. 같은 폴더의 것을 `<link rel="stylesheet" href="style.css">`로 참조합니다.

## 공통 규칙 (깨뜨리지 말 것)

- **인라인 스타일 금지.** 모든 CSS는 `style.css` 파일로 분리. `<style>` 블록도 쓰지 않음
- **프레임워크 금지.** React·번들러·npm 없음. 브라우저에서 파일을 바로 열어도 동작해야 함
- **전 페이지 한국어**, 반응형 (모바일에서 사이드바가 서랍으로, 그리드가 스택)
- 구글 폰트는 각 `style.css` 최상단 `@import`로 로드
- 가이드 사이트의 JS는 **`ide.js` 한 파일**에 모읍니다 (HTML 안에 `<script>` 블록을 쓰지 않음). `sample/`은 예전대로 각 HTML 하단 인라인 스크립트
- localStorage 사용처: `sample/`은 글 데이터, 가이드는 **UI 상태와 비밀번호**(테마 · 사이드바 접힘 · 잠금 해제 여부). **체크리스트는 저장하지 않습니다** — 여러 사람이 돌려 보는 문서라 앞사람의 체크가 남으면 헷갈립니다. 저장이 막혀 있어도 페이지는 정상 동작해야 함
- 프롬프트 복사는 `navigator.clipboard.writeText()` + textarea 폴백

## 사이트 1 — 워크샵 가이드 (루트)

### 컨셉

**코드 에디터의 분위기만 빌려온 문서 화면.** 위에 한 줄짜리 타이틀바(신호등 + 지금 보는 파일 경로), 왼쪽에 문서 목록 사이드바, 아래에 얇은 상태바. 그게 전부입니다. `Ctrl+P` 명령 팔레트로도 문서 사이를 이동할 수 있고, 각 프롬프트는 터미널 창(맥 신호등 도트 + 파일명 + COPY 버튼) 스타일입니다.

**의도적으로 두지 않은 것** — 메뉴바(파일/편집/…), 액티비티바(아이콘 레일), 탭바, 빵부스러기, 줄번호 거터, 미니맵, 하단 터미널 패널. 전부 있었다가 뺐습니다. 읽는 데 도움이 안 되고, 특히 **탭바는 사이드바와 같은 목록을 두 번 보여주는 중복**이었습니다. 문서 이동 수단은 사이드바 하나로 유지하세요.

브라우저 창 전체가 에디터입니다. `body`는 `overflow:hidden`이고 **본문 스크롤은 `.scroller`가 담당**합니다(`window`가 아니라 이 요소를 스크롤시켜야 합니다).

### 디자인 토큰 (`style.css`)

```css
/* 표면 */
--bg:#0b0d10;       --editor:#0d1015;   --panel:#111317;   --panel-2:#14171c;
--sidebar:#0a0c0f;  --chrome:#101318;   --hover:#171b21;
--border:#22262c;   --border-soft:#191d23;
/* 글자 */
--text:#d4d8dd;     --text-dim:#7d8590; --text-faint:#565d68;
/* 구문 강조 */
--blue:#569cd6;     --green:#6a9955;    --green-bright:#3ddc84;
--orange:#ce9178;   --purple:#c586c0;   --yellow:#dcdcaa;
--red:#f14c4c;      --cyan:#4ec9b0;
/* 강조 조합 · 치수 */
--accent / --accent-bg / --accent-line / --status / --selection
--h-title --h-status --w-sidebar --line-h
```

**라이트 테마**는 `html[data-theme="light"]`에서 같은 토큰을 다시 정의합니다(Light+ 계열). 색을 새로 쓸 때는 하드코딩하지 말고 토큰을 쓰거나, 라이트 값도 함께 추가하세요.

폰트: 헤딩/코드/라벨 `JetBrains Mono`, 본문 `IBM Plex Sans KR`.

### 페이지 공통 구조

HTML에는 **빈 껍데기만** 두고 내용은 `ide.js`가 채웁니다. 9개 페이지가 아래 뼈대를 글자 그대로 공유하며, 페이지마다 다른 것은 `<title>`, `<body data-file="...">`, `.main` 안의 본문뿐입니다.

```html
<body data-file="step1.html">
<div class="ide">                    <!-- grid 세 줄: 타이틀 / 본체 / 상태바 -->
  <header class="titlebar"></header>  <!-- 신호등 · ▤ 토글 · 파일 경로 · 검색 · 테마 -->
  <div class="workbench">             <!-- grid 두 칸: 252px / 1fr -->
    <aside class="sidebar"></aside>   <!-- 문서 목록 / 완성본 데모 / 이 문서 안에서 -->
    <div class="editor">
      <div class="editor-area">
        <div class="scroller" id="scroller">
          <div class="code">
            <main class="main"> … 본문 … </main>
          </div>
        </div>
      </div>
    </div>
  </div>
  <footer class="statusbar"></footer>
</div>
<script src="ide.js"></script>
```

`.editor` · `.editor-area` · `.scroller` · `.code`는 지금은 단순 래퍼입니다. 그래도 `.scroller`는 스크롤 주체라 반드시 필요하고, **`.editor-area`에는 `min-width:0`이 있어야 합니다.** 그리드 항목이라 이게 없으면 넓은 자식(흐름 다이어그램 등) 때문에 폭이 늘어나 좁은 화면에서 본문 글자가 잘립니다.

### `ide.js`가 하는 일

문서 목록은 파일 맨 위 **`FILES` 배열이 유일한 출처**입니다. 여기만 고치면 사이드바·명령 팔레트·상태바 "문서 n/9"이 한꺼번에 따라옵니다. 배열 순서가 곧 사이드바에 찍히는 번호이자 워크샵 진행 순서입니다.

| 기능 | 설명 |
|---|---|
| 골격 생성 | 타이틀바 · 사이드바 · 상태바 |
| 개요(이 문서 안에서) | 본문 `h2`/`h3`를 훑어 `id`를 붙이고 사이드바 목록 생성 |
| 스크롤 추적 | 지금 읽고 있는 섹션을 개요에서 강조 |
| 명령 팔레트 | `Ctrl+P` 파일 · `@` 문서 내 제목 · `>` 명령. 부분일치(subsequence) 검색 |
| 그 밖 | COPY 버튼, 체크리스트 토글(**저장하지 않음** · 상태바 숫자는 `.hostbox` 밖 항목만 셈), 테마 전환, 사이드바 접기, 잠금 처리 |

단축키: `Ctrl+P` 팔레트 · `Ctrl+K` 명령 · `Ctrl+B` 사이드바 · `Esc` 닫기 (맥은 `⌘`).

### 문서 접근 제한 (워크샵 당일 공개)

`index.html`을 뺀 나머지 8개 문서는 **워크샵 당일 0시에 자동으로 열립니다.** 그 전에는 잠금 화면(`.lockbox`)이 본문 자리를 차지하고, **비밀번호**를 넣으면 바로 열립니다.

설정은 `ide.js` 맨 위 세 줄이 전부입니다.

```js
var OPEN_AT  = new Date(2026, 7, 30, 0, 0, 0);   // 공개 시각 (월은 0부터 — 7 = 8월)
var PASSCODE = '1021';                            // 미리 여는 비밀번호
var FREE     = ['index.html'];                    // 언제나 열려 있는 문서
```

동작:

- **공개 전** — 잠긴 문서는 본문이 잠금 화면으로 교체되고, 사이드바·팔레트에 자물쇠(`.lk`)가 붙습니다. 상태바에는 `🔒 D-n`이 나옵니다
- **열린 문서**(index)에는 "나머지는 당일 공개" 안내 콜아웃이 자동으로 붙습니다 (`lockNotice()`). 공개일이 지나면 안내는 저절로 사라집니다
- **코드 입력** — 맞으면 `localStorage`에 기록하고 새로고침, 이후 모든 문서가 열립니다. 틀리면 입력칸이 흔들리고 메시지가 뜹니다
- **코드로 열어둔 상태 표시** — 코드를 넣어 열어둔 브라우저에서는 모든 문서 맨 위에 `🔓 비밀번호로 열어 둔 상태입니다` 배너가 붙습니다(`passNotice()`). 이게 없으면 진행자가 **"왜 안 잠겨 있지?"** 하고 헷갈립니다 — 참가자 화면에서는 여전히 잠겨 있는데 내 브라우저에만 비밀번호가 남아 있는 상황이거든요. 공개일이 지나면 배너는 나오지 않습니다
- **되돌리기** — 그 배너의 `잠금 다시 걸기` 버튼, 상태바의 `🔓 비밀번호로 열림`, 팔레트의 `잠금 다시 걸기` 셋 중 아무거나 누르면 기록이 지워지고 참가자와 같은 화면이 됩니다

> ⚠️ **이건 커튼이지 보안이 아닙니다.** 정적 사이트라서 잠긴 문서의 HTML은 브라우저 소스 보기나 공개 GitHub 저장소에서 그대로 읽을 수 있습니다. 화면에서 미리 열어보지 못하게 막는 용도이지, 내용을 지키는 장치가 아닙니다. 진짜로 가려야 하는 내용이라면 워크샵 전까지 저장소를 비공개로 두거나, 해당 문서를 나중에 커밋하세요.

### 문서에 담는 원칙 — 진행자가 말로 하던 것을 글로

이 사이트는 **진행자 없이 읽어도 흐름이 이어지는 것**을 목표로 합니다. 워크샵 당일 진행자가 구두로 설명하던 내용(개념 비유, 도구 소개, 운영 요령, 자주 나오는 질문)을 문서 안에 넣어두었습니다. 그래서 각 페이지는 대략 이 순서를 따릅니다.

```
badge · h1 · subtitle · lead      한 문단으로 "지금 뭘 하는지"
.brief                            할 일 / 시간 / 끝나면 (3~4줄)
개념 한 문단 + .flow              필요할 때만. 자세한 건 .more로 접음
h2 1. → 2. → 3. → 4.              손이 움직이는 순서 그대로
.qa                               자주 나오는 질문
details.hostbox                   🎤 진행자 운영 요령 — 맨 뒤, 접힌 채로
.pagenav
```

읽는 사람은 **겁먹은 비개발자**입니다. 그래서 규칙이 셋 있습니다.

1. **본문은 손이 움직이는 순서만.** STEP 문서의 `h2`는 `<span class="stepno">1.</span>` 처럼 번호를 답니다. "왜 이렇게 하는지", "이 프롬프트가 잘 만들어진 이유" 같은 곁가지는 `details.more`로 접어서 흐름을 끊지 않습니다
2. **진행자용은 접어서 맨 뒤로.** `details.hostbox`(🎤, 청록)에 넣습니다. 참가자가 읽어도 되는 내용이지만, 본문 한가운데 있으면 "나한테 하는 말인가?" 하고 멈칫하게 됩니다. 삭제가 아니라 **접기**인 이유는 진행자도 같은 문서를 쓰기 때문입니다
3. **참가자용 조언은 `.callout.tip`(초록)으로 펼쳐 둡니다.** 겁을 덜어주는 문장("옆 사람과 달라도 정상입니다")은 접으면 의미가 없습니다

그 밖에:

- `.qa`와 `details.hostbox`/`details.more`는 전부 네이티브 `<details>`라 **JS 없이 접힙니다**
- 개요(아웃라인)에는 `.steps`와 `.qa` 안의 `h3`를 넣지 않습니다. 단계 카드 제목까지 넣으면 목록이 두 배로 길어져서 훑기 어려워집니다

### 페이지별 내용

### 주제는 참가자가 고릅니다

완성본 데모는 책후기 게시판이지만, **참가자는 STEP 1 첫 단계에서 각자 주제를 정합니다.** 데이터 구조(네 칸)가 같으면 만드는 방법이 동일하다는 게 핵심 아이디어예요.

| 주제 | 네 칸 |
|---|---|
| 📚 책·영화 후기 **(기본)** | 제목 · 작성자 · 작성일 · 내용 |
| ⭐ 별점 랭킹 | 대상 · 추천인 · 별점 · 한줄평 |
| 🎨 오늘의 기분 | 날짜 · 이름 · 기분 · 한 줄 |
| 💰 회비·지출 장부 | 날짜 · 이름 · 항목 · 금액 |
| ❓ 오늘의 질문 | 날짜 · 이름 · 질문 · 답 |

- **기본 프롬프트는 그대로 두고, `○○` 자리를 비운 변형본을 따로 둡니다.** step1의 `step1-prompt-custom.txt`(+ 채워 쓴 예 `example-rating.txt`)가 그것이고, 기본 경로를 방해하지 않도록 `.more`에 접어 두었습니다
- **step2에서는 두 곳만 바꾸면 됩니다** — 프롬프트 첫 줄의 "게시판 웹사이트", 그리고 "시트 컬럼 구조는 [...]" 줄. 이 안내를 `.callout`으로 프롬프트 바로 아래 붙여 두었습니다
- **extra의 답변달기 프롬프트는 기본 주제 기준**이라, 다른 주제면 "답변"을 자기 칸으로 바꾸라는 안내가 앞에 붙어 있습니다
- 진행자 지침: **2분 안에 못 고르면 기본으로 보냅니다.** 6명이 다 달라도 막히는 지점은 같습니다
- **주제는 사전 안내문으로 미리 굴립니다.** checklist의 복사용 안내문에 주제 예시가 들어 있어, 참가자가 워크샵 전에 생각해오면 당일 2분을 아낍니다. 다만 문서에 **"강요하지 말 것"**을 명시했습니다 — 숙제가 되면 부담을 느껴 안 오는 사람이 생깁니다

### 구현 포인트

- **타임라인** — `.timeline::before`가 왼쪽 세로 점선, 각 `.tl-item .marker`가 📖 원형 마커
- **카드 색 순환** — `.tl-card.c1/.c2/.c3` = 핑크 / 라벤더 / 피치. JS에서 `'c' + (i % 3 + 1)`로 부여

### 페이지별 내용

**index.html** — 헤더 → 히어로("우리가 읽고 남긴 이야기들" / "이번 달 읽은 책, 어땠나요?") → **"✏️ 새 후기 남기기" 버튼** → 타임라인 → 마무리 문구.

> ⚠️ **글쓰기 버튼은 반드시 타임라인 시작 전(히어로 바로 아래)에 있어야 합니다.** 글이 많아져도 스크롤 없이 글을 쓸 수 있어야 한다는 요구사항입니다. 하단으로 옮기지 마세요.

- 각 카드: 날짜 · 작성자 / 제목 / 내용 요약(64자, 넘으면 `…`)
- 목록 맨 아래: 점선 구분선 + "🍵 여기까지가 지금까지의 기록이에요" (버튼 없이 텍스트만)
- 글이 없을 때: "아직 등록된 후기가 없어요 / 위 버튼으로 첫 책후기를 남겨보세요"

**write.html** — 노트카드 스타일 폼(책 제목·후기 제목 / 이름 / 내용). placeholder 예시는 "예: 아몬드 — 다시 읽어도 좋은 책". 제출 시 localStorage 저장 후 `index.html`로 리다이렉트.

**detail.html** — 큰 따옴표 장식 + 제목 + 작성자·날짜 + 본문 + "← 목록으로 돌아가기". `?id=` 쿼리스트링으로 글을 찾고, 없으면 "후기를 찾을 수 없어요" 표시.

## 결정 기록 (왜 이렇게 되어 있는가)

작업 순서대로, 나중에 되돌리지 않도록 이유를 남깁니다.

1. **진행자용 팁 페이지는 만들지 않음** — 초안에 있었으나 불필요하다고 판단해 제외. 진행자용 내용은 각 페이지의 콜아웃(`.callout.tip`)으로 분산시켰습니다.
2. **상세보기 큰따옴표는 세리프 폰트** — 한글 손글씨체(당시 Kirang Haerang)로 두니 `“` 글리프가 66px에서도 작게 그려졌습니다. `.article .quote`만 Georgia 계열로 고정.
3. ~~**모바일에서 Explorer는 가로 스크롤 탭 줄로 변형**~~ — 세로 파일 목록을 그대로 두니 휴대폰에서 첫 화면을 사이드바가 통째로 차지했습니다. **6번 결정으로 서랍(drawer) 방식으로 대체되었습니다.**
4. **sample 폰트 교체 (Kirang Haerang + Jua → Gowun Batang + IBM Plex Sans KR)** — "더 깔끔한 폰트로" 요청. 명조는 같은 px에서 더 커 보이므로 히어로 40→37px, 카드 제목 23→21px, 상세 제목 30→27px, 모바일 히어로 29→26px로 함께 줄였고, 본문 굵기는 300→400으로 올려 한글 획이 흐려지지 않게 했습니다. **컬러·스캘럽·하드섀도우·타임라인 구조는 유지.**
5. **index.html의 "문서 목록" 카드 그리드 삭제** — 사이드바 Explorer와 하단 pagenav가 이미 같은 이동 경로를 제공해서 중복이었습니다. 안 쓰게 된 `.doc-grid` / `.doc-card` CSS도 함께 제거했습니다. index 흐름은 이제 **소개 → 오늘의 흐름 → 완성본 CTA → 세 단어만 기억하세요**.
6. **가이드 사이트를 "에디터 흉내"에서 "에디터 워크벤치"로 확장** — 액티비티바 · 빵부스러기 · 줄번호 거터 · 미니맵 · 하단 터미널 패널 · 명령 팔레트 · 라이트 테마를 더해 화면 전체가 에디터로 보이게 했습니다. **이 중 껍데기 부분은 14번에서 다시 걷어냈습니다**(명령 팔레트·라이트 테마·`ide.js` 구조는 남았습니다). 이때 함께 바뀐 세 가지는 지금도 유효합니다.
   - **공통 UI를 `ide.js` 한 파일로 이동.** 같은 골격을 8개 HTML에 복사해두면 문서를 하나 추가할 때 8곳을 고쳐야 했습니다. 이제 `FILES` 배열 한 줄이면 됩니다. HTML에는 빈 컨테이너만 남습니다.
   - **스크롤 주체가 `window` → `.scroller`로.** 화면 높이에 고정돼야 상태바가 항상 제자리에 있습니다. `body`는 `overflow:hidden`입니다.
   - **모바일 문서 목록은 가로 탭 줄 대신 서랍(drawer)으로.** 문서가 8개로 늘면서 가로 스크롤 줄로는 어디에 있는지 알기 어려웠습니다. 타이틀바의 ▤ 버튼이나 `Ctrl+B`로 열고, 바깥을 누르면 닫힙니다. (3번 결정을 대체합니다.)

7. **문서 접근 제한은 날짜 OR 코드** — 워크샵 전에 참가자가 STEP들을 미리 훑어보면 당일 진행이 늘어집니다. 그렇다고 진행자가 매번 열어줘야 하면 번거로워서, **당일 0시 자동 공개**와 **비밀번호**를 OR로 걸었습니다. 잠금 화면은 별도 페이지가 아니라 `.main` 본문을 통째로 교체하는 방식이라, 잠긴 문서의 내용이 DOM에 남지 않습니다(소스 보기로는 여전히 보입니다 — 위 경고 참고).
8. **`<pre>` 안쪽은 절대 들여쓰지 않음** — 6번 리팩터링에서 본문을 한 단계 더 깊게 넣으면서 `<pre>` 내부 줄에도 공백 6칸이 붙었고, COPY 버튼으로 복사한 프롬프트에 그 공백이 그대로 따라갔습니다. `<pre>`는 공백을 그대로 보여주는 태그라 바깥 들여쓰기와 무관하게 **왼쪽 끝에 붙여** 써야 합니다. 페이지 골격을 다시 손볼 때 같은 실수를 반복하지 마세요.

9. **진행자 설명을 문서로 흡수** — 원래 개념 설명·운영 요령·자주 나오는 질문은 진행자 머릿속에 있었습니다. 그러면 ① 진행자가 바뀌면 품질이 흔들리고 ② 참가자가 나중에 혼자 복습할 수 없습니다. 그래서 전부 문서에 넣고, 대신 길어진 문서를 훑을 수 있도록 `.brief`(상단 요약) · `.flow`(개념 다이어그램) · `.qa`(접히는 질문) · `.gloss`(용어 사전)를 만들었습니다. **문서를 더 넣을 때도 "읽는 사람이 훑을 수 있는가"를 먼저 보세요.** 문단을 늘리기보다 요약 카드·표·접기로 정리하는 쪽이 이 사이트의 방향입니다.

10. **내용을 넣은 뒤 순서를 다시 잡음** — 9번에서 설명을 잔뜩 채웠더니 문서가 산발적으로 읽혔습니다. 특히 step1은 코드를 받기 전에 붙여넣는 법이 먼저 나왔습니다. 그래서 ① STEP 문서를 **번호 붙은 실행 순서**로 다시 배열하고 ② 곁가지(이론·이유)는 `details.more`로 ③ 진행자 지침은 `details.hostbox`로 접어 맨 뒤로 보냈습니다. templates는 **예시를 이론 앞으로** 옮기고 쪼개기·인터뷰를 "여기서부터는 심화"로 묶었으며, index는 **데모를 흐름표보다 먼저** 두었습니다(보여주고 나서 설명). errors의 "진행자용 패턴 매칭표"는 참가자도 쓰는 내용이라 **"증상별로 원인 찾기"로 이름만 바꿔 본문에 남기고**, 운영 지침만 접었습니다.

11. **templates를 둘로 쪼갬** — 한 문서에 "네 칸 템플릿 + 쪼개기 + 인터뷰"가 다 있으니 5800px가 됐습니다. 당일 STEP 1 직전에 3분 만에 읽어야 하는 문서로는 너무 길었어요. 그래서 **당장 쓰는 것만 `templates.html`(2500px)에 남기고, 심화 두 가지를 `tips.html`로 분리**했습니다. 문서 순서에서 tips를 맨 뒤(부록 자리)에 둔 것도 같은 이유입니다 — 워크샵 진행 경로(index → checklist → templates → STEP 1~3 → extra → errors)를 건드리지 않기 위해서입니다. templates 끝의 `.cta`가 "오늘은 안 읽어도 됩니다"라고 명시하며 연결합니다.

12. **주제를 참가자가 고르게 함** — "게시판"이 너무 뻔하고, 다 만들고 나서 아무도 안 쓴다는 문제가 있었습니다. 주제를 통째로 바꾸는 대신 **네 칸 구조는 고정하고 주제만 고르게** 했습니다. 프롬프트·시트·코드 난이도가 하나도 안 오르면서 결과물은 6개가 다 달라지고, 진행자가 6가지 다른 문제를 떠안지도 않습니다. 기본 프롬프트를 지운 게 아니라 **변형본을 옆에 접어 둔** 것도 같은 이유예요 — 못 고른 사람은 기본으로 가면 그만입니다.

13. **주제 선택을 워크샵 전으로 당김** — 당일에 고르면 2분이 날아가는 것보다 "고민하느라 손이 멈추는" 게 더 큰 손해였습니다. checklist에 **복사해서 단톡방에 붙여넣는 사전 안내문**을 넣어 준비물과 주제 예시를 한 번에 보내게 했습니다. step1의 주제 고르기 단계는 그대로 두었습니다 — 미리 정해온 사람은 확인만 하고 넘어가고, 못 정한 사람은 거기서 고르면 되니까요.

14. **에디터 껍데기를 도로 걷어냄 (6번의 부분 되돌리기)** — 워크벤치를 다 갖추고 나니 화면이 과했습니다. 특히 **사이드바와 탭바가 같은 문서 목록을 두 번** 보여줬고, 하단 터미널은 가짜 로그를 띄우느라 세로 공간만 190px 먹었습니다. 그래서 메뉴바 · 액티비티바 · 탭바 · 빵부스러기 · 줄번호 거터 · 미니맵 · 하단 패널을 전부 제거하고 **타이틀바 한 줄 + 사이드바 + 상태바**만 남겼습니다.

    - **남긴 기준** — 읽거나 이동하는 데 실제로 쓰이는 것만. 명령 팔레트(`Ctrl+P`)는 화면을 차지하지 않으면서 이동을 빠르게 해서 남겼고, 개요(`이 문서 안에서`)는 문서가 길어 필요했습니다. 잠금 · COPY · 체크리스트 저장 · 라이트 테마는 기능이라 그대로입니다.
    - **사이드바가 파일명 대신 문서 제목을 보여줍니다.** `step2.html`보다 `STEP 2 · Google Sheets 연동`이 비개발자에게 훨씬 빨리 읽힙니다. 파일명은 타이틀바에만 남겼습니다. 앞의 번호는 `FILES` 배열 순서 = 워크샵 진행 순서입니다.
    - **`.editor-area`에 `min-width:0`이 꼭 필요합니다.** 미니맵을 걷어내며 `.editor-area`가 열 지정 없는 그리드 항목이 됐는데, 그러면 넓은 자식 때문에 폭이 늘어나 좁은 화면에서 본문 글자가 오른쪽으로 잘립니다. 실제로 한 번 겪었습니다.
    - **다시 늘리지 마세요.** 에디터처럼 보이게 하는 장식은 여기까지가 상한선입니다.

15. **전날 문서와 당일 문서를 분리** — 한 페이지에 전날 준비와 당일 진행 대본이 섞여 있으니 참가자가 "내가 지금 뭘 봐야 하지?"에서 멈췄습니다. **참가자는 `checklist.html`까지만** 보면 되도록 자르고, 당일 운영은 `dday.html`로 옮겨 **당일 공개 잠금**을 걸었습니다. 사전 안내문도 체크리스트와 한 페이지에 합쳐, 진행자가 그 문서만 열면 "무엇을 보내고 무엇을 준비할지"가 다 있게 했습니다. 진행자 사전 준비는 같은 문서에 두되 `.hostbox`로 접었습니다.
16. **와이파이 속도 점검·핫스팟 백업 항목 삭제** — 실제로 확인하기 어렵고, 준비 목록이 길어질수록 진짜 중요한 항목(계정·주제)의 밀도가 떨어집니다.

17. **1페이지 = 개요 + 체크리스트, 2페이지 = 오늘 수업** — 문서가 늘면서 참가자가 "뭘 봐야 하지"에서 멈췄습니다. `checklist.html`을 없애고 **전날 준비를 index로 끌어올려**, 워크샵 전에 볼 것을 첫 페이지 하나로 줄였습니다. 대신 index에 있던 개념 설명(세 단어 · 도구 · 배우는 것 · 질문 · 용어)은 **당일 문서(`dday.html`)로 내려보냈습니다** — 전날에는 읽어도 와닿지 않는 내용이라서요. 사전 안내문과 진행자 준비는 index 맨 아래 🎤 상자로 접었습니다.
18. **체크리스트는 저장하지 않습니다** — 이전에는 `localStorage`에 남겼는데, 여러 사람이 돌려 보는 문서라 앞사람이 체크해둔 상태가 남으면 다음 사람이 헷갈립니다. 지금은 **누르면 취소선만 그어지고 새로고침하면 풀립니다.** 상태바 숫자도 `.hostbox` 밖(참가자용) 항목만 셉니다.

## 로컬에서 보기

```bash
python3 -m http.server 8899
```

`http://localhost:8899/` → 가이드, `http://localhost:8899/sample/` → 데모.

파일을 직접 열어도(`file://`) 동작하지만, 그때는 클립보드 API가 막혀 COPY 버튼이 textarea 폴백으로 넘어갑니다.

JavaScript를 끄면 에디터 UI(탭·탐색기·팔레트) 없이 본문만 보이고, 각 페이지 맨 위 `<noscript>` 안내에 문서 이동 링크가 나옵니다.

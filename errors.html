에러 해결법

빨간 글씨는 나쁜 소식이 아니라 힌트입니다

개발자도 하루 종일 에러를 봅니다. 다른 점은 딱 하나예요. 에러 메시지를 읽어본다는 것. 오늘 여러분이 배울 건 에러를 안 내는 법이 아니라, 에러가 났을 때 그 문장을 복사해서 AI에게 건네는 습관입니다.

1. 콘솔 여는 법

콘솔은 브라우저가 우리에게 말을 거는 창입니다. 화면에는 아무 일 없어 보여도, 여기에는 무슨 일이 있었는지 적혀 있어요.

운영체제단축키
맥Cmd + Option + I
윈도우F12  또는  Ctrl + Shift + I

창이 열리면 위쪽 탭 중에서 Console을 누르세요. Elements, Network 같은 다른 탭은 오늘 안 씁니다.

2. 원칙은 하나뿐입니다

⛔ 빨간 글씨 = 에러

콘솔에 빨간 글씨가 있으면 그게 원인입니다. 회색이나 노란 글씨는 지금 무시해도 됩니다. 빨간 줄을 찾아서 드래그로 선택 → 복사하세요. 그게 첫 번째 행동입니다.

빨간 글씨가 여러 줄이면 제일 위의 것부터 보세요. 아래쪽은 대개 그 여파로 따라 나온 것들입니다.

3. 에러 해결 프롬프트

복사한 에러를 아래 틀에 넣어서 AI에게 그대로 보내세요. 이게 오늘 워크샵에서 가장 많이 쓰게 될 프롬프트입니다.

error-prompt.txt
[상황/맥락] 나는 (무엇을 하려고 했는지)를 하고 있었는데 이런 에러가 떴어:

(콘솔에서 복사한 에러 메시지 붙여넣기)

내 코드는 이거야:

(관련 코드 파일 내용 붙여넣기)

[요청] 원인이 뭔지 알려주고, 어떻게 고쳐야 할지 알려줘.

[형식] 수정된 전체 코드로 다시 줘. 어디를 왜 고쳤는지도 짧게 설명해줘.
✱ 코드도 같이 붙여넣어야 합니다

에러 메시지만 보내면 AI는 일반론만 말해줍니다. 에러 + 코드를 함께 줘야 "여기 이 줄이 문제네요"라는 답이 옵니다. 파일 전체를 붙여넣는 걸 겁내지 마세요.

4. 진행자용 에러 패턴 매칭표

워크샵에서 반복해서 나오는 네 가지입니다. 증상만 들어도 원인이 짐작되면 대응 속도가 크게 달라집니다.

콘솔 증상원인
Failed to fetch / CORS 에러 Apps Script 웹앱 URL 오류 또는 액세스 권한 미설정
데이터 안 불러와지는데 에러도 없음 Sheets 컬럼 순서와 코드 참조 순서 불일치
Uncaught SyntaxError 코드 복붙 중 일부 누락
배포됐는데 화면 하얗게 뜸 파일 경로(html/js/css) 오류

각 패턴 대응 요령

  • 1

    Failed to fetch / CORS

    가장 흔합니다. 순서대로 확인하세요.

    • 코드에 붙여넣은 URL이 /exec로 끝나나요? /dev로 끝나면 안 됩니다.
    • 배포 설정에서 액세스 권한이 모든 사용자인가요?
    • 코드를 고친 뒤 새 버전으로 재배포했나요?
    • 웹앱 URL을 브라우저 주소창에 직접 넣어보세요. 뭔가 응답이 보이면 URL은 정상입니다.
  • 2

    에러는 없는데 데이터가 안 나옴

    시트 첫 행이 제목 · 작성자 · 작성일 · 내용 순서인지 확인하세요. 순서를 바꿔놓고 코드는 그대로면, 제목 자리에 작성자가 들어가는 식으로 어긋납니다. 시트를 고치든 코드를 고치든 둘 중 하나를 맞추면 됩니다.

  • 3

    Uncaught SyntaxError

    코드를 복사할 때 일부가 빠진 경우입니다. 부분 수정하려 하지 말고, AI에게 "전체 코드를 다시 줘"라고 한 뒤 파일 내용을 통째로 지우고 새로 붙여넣는 게 가장 빠릅니다.

  • 4

    배포했는데 화면이 하얗게 뜸

    파일 이름과 경로 문제입니다.

    • 저장소 맨 위에 index.html이 있어야 합니다. 폴더 안에 들어가 있으면 안 열립니다.
    • 대소문자를 구분합니다. Style.css와 style.css는 다른 파일이에요. 내 컴퓨터에서는 되던 게 배포하면 깨지는 대표적 원인입니다.
    • C:\Users\... 같은 내 컴퓨터 경로가 들어가 있으면 안 됩니다.
✱ 그래도 안 될 때의 마지막 카드

10분 넘게 같은 자리에서 돌고 있다면, 고치려 하지 말고 다시 만드는 게 빠를 때가 많습니다. 새 대화를 열고 STEP 1 프롬프트부터 다시 시작하세요. 두 번째는 훨씬 빠릅니다. 되돌아가는 게 지는 게 아니에요.

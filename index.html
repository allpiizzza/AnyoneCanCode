비개발자 웹사이트 워크샵

코드를 한 줄도 몰라도 괜찮습니다

오늘, 우리 동네 게시판을 함께 설계하고 붙입니다. 개발자가 아니어도 됩니다. 필요한 건 노트북 한 대와 "이런 걸 만들고 싶다"는 문장 하나예요. 그 문장을 AI에게 어떻게 건네는지만 익히면, 오늘 안에 인터넷 주소가 있는 진짜 웹사이트를 하나 갖게 됩니다.

이 워크샵은 프로그래밍을 가르치지 않습니다. 대신 원하는 걸 정확하게 말하는 법과, 만들어진 결과물을 세상에 올려두는 법을 다룹니다. 오늘 다 못 만들어도 괜찮아요. 여기 문서는 워크샵이 끝난 뒤에도 그대로 남아 있습니다.

오늘의 흐름

시간내용
15분완성본 시연 + 개념 설명 (프론트 / 백 / 배포란?)
20분계정 생성 (Replit, GitHub, Vercel)
45분AI 프롬프트로 목록 · 글쓰기 · 상세보기 화면 만들기
30분Google Sheets 연동 (저장 / 불러오기)
20분GitHub + Vercel 배포 → 실제 URL 접속
나머지자유 커스터마이징 · Q&A · (여유 시) 답변달기, 도메인 연결
🎤 진행자용 — 시연 순서 (5분)

말로 설명하기 전에 데모부터 보여주세요. 순서는 이렇게 하면 막힘이 없습니다.

  • ① 목록 화면을 먼저 보여줍니다. "이게 오늘 만들 겁니다."
  • ② 새 후기 남기기 → 글을 하나 씁니다. 참가자 이름을 넣으면 반응이 좋습니다.
  • ③ 등록을 누르고 목록에 바로 뜨는 걸 보여줍니다. 여기가 핵심 장면입니다.
  • ④ 휴대폰으로 같은 주소를 엽니다. "여러분 폰에서도 열립니다"가 오늘의 동기부여입니다.
  • ⑤ 카드를 눌러 상세 화면까지 보여주고 마칩니다.

"내가 쓴 글이 화면에 남는다"는 경험 하나면 오늘의 목표 설명이 끝납니다. 코드 이야기는 아직 꺼내지 마세요.

오늘 나오는 모든 이야기는 결국 이 셋 중 하나입니다. 식당에 비유하면 이해가 빠릅니다.

STEP 1이 끝나면 화면은 멀쩡한데 새로고침하면 쓴 글이 없어집니다. 고장이 아닙니다. 홀만 만들고 창고를 아직 안 만들었기 때문이에요. 글을 어디에도 적어두지 않았으니 화면을 다시 그리는 순간 사라지는 겁니다. 그 창고를 STEP 2에서 붙입니다.

오늘 쓰는 도구 네 가지

이름이 낯설 뿐, 하는 일은 한 줄로 끝납니다. 지금 외우지 않아도 됩니다.

도구하는 일왜 이걸 쓰나
AI 채팅 내가 말로 부탁하면 코드를 써줍니다. 오늘 코드를 직접 쓰지 않기 위해서. 우리가 할 일은 부탁을 잘 하는 것뿐입니다.
Replit 브라우저 안의 작업실. 코드를 붙여넣고 바로 실행해 봅니다. 노트북에 아무것도 설치하지 않아도 되고, 맥·윈도우 차이가 없습니다.
Google Sheets 쓴 글이 쌓이는 창고. 이미 익숙하고, 저장된 내용을 눈으로 볼 수 있습니다. 진짜 데이터베이스는 그게 안 돼요.
GitHub + Vercel 코드를 보관하고(GitHub), 인터넷 주소로 띄웁니다(Vercel). 둘 다 무료이고, 한 번 연결하면 그다음부터는 자동입니다.

오늘 배우는 것과 배우지 않는 것

배웁니다배우지 않습니다
원하는 걸 AI에게 정확히 말하는 법 HTML·CSS·JavaScript 문법
결과를 확인하고 다음을 요청하는 리듬 코드를 직접 읽고 쓰는 능력
에러가 났을 때 대처하는 순서 에러가 안 나게 하는 법 (개발자도 못 합니다)
만든 걸 인터넷에 올리는 절차 서버·데이터베이스 같은 인프라 지식
✱ 오늘 결과물이 옆 사람과 달라도 정상입니다

같은 프롬프트를 넣어도 AI는 매번 조금씩 다른 코드를 줍니다. 색이 다르거나 카드 모양이 달라도 고장이 아닙니다. 화면이 뜨고 버튼이 눌리면 그걸로 성공이에요. 옆 사람과 똑같이 만드는 게 목표가 아닙니다.

자주 나오는 질문

코드를 정말 한 줄도 몰라도 되나요?

됩니다. 오늘 여러분이 하는 일은 부탁하기 · 복사하기 · 붙여넣기 · 눈으로 확인하기 네 가지입니다. 코드는 읽지 않아도 됩니다. 다만 "여기를 고쳐야겠다"는 말은 직접 하셔야 해요. 그 말을 잘 만드는 법이 오늘의 핵심입니다.

돈이 드나요?

오늘 쓰는 것은 전부 무료 범위 안에서 끝납니다. Replit·GitHub·Vercel·Google Sheets 모두 무료 계정으로 충분해요. 유료가 되는 건 방문자가 아주 많아지거나 한글 도메인 같은 주소를 따로 사는 경우뿐입니다.

오늘 만든 사이트는 계속 남아 있나요?

남습니다. 계정을 지우지 않는 한 주소는 계속 살아 있어요. 내일도, 한 달 뒤에도 같은 주소로 들어갈 수 있습니다. 글은 여러분의 Google 스프레드시트에 쌓이니 그것도 그대로 남습니다.

AI가 틀린 코드를 주면 어떻게 하나요?

자주 있는 일이고, 그게 정상입니다. 대응은 늘 같습니다.

  • 화면에 안 나오면 → 콘솔을 열고 빨간 글씨를 복사
  • 그 빨간 글씨를 AI에게 그대로 붙여넣기
  • "수정된 전체 코드로 다시 줘"라고 덧붙이기

자세한 순서는 에러 해결법에 있습니다.

워크샵이 끝나고 혼자서 고칠 수 있을까요?

오늘 쓰는 방식 그대로 하시면 됩니다. AI 대화창을 열고 "지금 이런 사이트를 만들어뒀는데, 여기를 이렇게 바꾸고 싶어"라고 하면 돼요. 범용 프롬프트 템플릿 문서를 그때 다시 열어보세요. 오늘 이후에도 계속 쓰라고 만든 문서입니다.

노트북 없이 태블릿이나 휴대폰으로도 되나요?

권하지 않습니다. 코드를 복사해서 붙여넣는 작업이 많은데 화면이 작으면 그 과정이 몇 배로 힘듭니다. 노트북과 충전기를 꼭 챙겨 오세요.

중간에 못 따라가면 어떡하죠?

진행자가 네 번 멈춰서 확인합니다(계정 생성 후 · 화면 완료 후 · 저장 연동 후 · 배포 후). 그때 손만 들어주세요. 그리고 이 문서는 워크샵이 끝나도 그대로 남아 있으니, 집에서 이어서 해도 됩니다.

용어 사전

오늘 귀에 스칠 단어들입니다. 뜻만 알면 충분하고, 외울 필요는 없습니다.

HTML
화면의 뼈대. 제목·글·버튼이 무엇인지 적어둔 것.
CSS
꾸미기. 색·크기·간격처럼 어떻게 보일지를 정합니다.
JavaScript
움직임. 버튼을 누르면 무슨 일이 일어날지 정합니다.
콘솔
브라우저가 우리에게 말을 거는 창. 에러가 여기 적힙니다.
배포
내 컴퓨터에 있던 걸 인터넷 주소로 올리는 일.
저장소(repository)
GitHub에 만드는 코드 보관함. 프로젝트 하나에 하나씩.
Push
내가 고친 코드를 그 보관함으로 올려 보내는 것.
API
프로그램끼리 주고받는 창구. 오늘은 화면과 스프레드시트를 잇는 통로입니다.
프롬프트
AI에게 건네는 부탁 문장. 오늘 진짜로 배우는 건 이것입니다.

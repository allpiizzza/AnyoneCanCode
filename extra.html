⚠ Apps Script 재배포 잊지 마세요

답변 저장은 Apps Script 코드도 같이 바뀝니다. 코드를 붙여넣은 뒤 배포 → 배포 관리 → 수정 → 새 버전 → 배포까지 해야 반영됩니다.

② Notion으로 갈아타기 가장 어려움

스프레드시트는 시작하기 쉬운 대신 제약이 많습니다. 글이 길어지면 칸이 답답하고, 이미지나 정리된 문서를 담기도 어렵죠. Notion으로 바꾸면 그 제약이 대부분 사라집니다. API도 스프레드시트보다 훨씬 안정적이에요.

대신 지금 주소로는 안 됩니다. 오늘 배포한 GitHub Pages는 만들어둔 파일을 그대로 보여주는 방식이라, 무언가를 실행하지는 못하거든요.

붙이고 싶은 것지금 주소로 되나이유
Google 스프레드시트 (오늘 한 것)✅ 됩니다브라우저에서 바로 부를 수 있음
Supabase · Firebase✅ 됩니다같은 이유
Notion API❌ 안 됩니다비밀 키를 숨겨야 해서 중간에 서버가 필요

그래서 이 과제는 Vercel로 옮기는 것까지 포함합니다. 같은 GitHub 저장소를 가져가기만 하면 되고, 오늘 만든 GitHub Pages 주소는 그대로 둡니다 — 진짜 자산은 저장소이지 배포 서비스가 아니거든요.

⛔ 오늘은 하지 마세요

이건 집에 가서 시간을 들여 하는 과제입니다. 서버 개념이 하나 들어와서 앞의 둘과 난이도가 다릅니다. 워크샵 시간에 시작하면 배포까지 못 끝내고 애매하게 남습니다.

왜 Vercel이 필요한가요

Notion API는 브라우저에서 직접 부를 수 없습니다. 이유가 둘입니다.

  • 비밀 키로 인증합니다. 화면 코드에 넣으면 소스 보기로 누구나 가져가서 내 Notion을 마음대로 건드릴 수 있습니다
  • 브라우저 요청을 막아둡니다. 실제로 확인해보면 허용 헤더를 아예 주지 않습니다

그래서 내 사이트와 Notion 사이에 심부름꾼을 하나 둡니다. 키는 그 심부름꾼만 알고, 화면은 심부름꾼에게만 말을 겁니다. 그 심부름꾼을 공짜로 얹어주는 게 Vercel이에요. GitHub Pages로는 안 됩니다 — 파일을 보여줄 뿐 무언가를 실행하지는 못하거든요.

    • Type은 Internal
  • 2

    키 복사해서 메모장에

    만들고 나면 Internal Integration Secret이 나옵니다. ntn_으로 시작하는 긴 글자예요. 복사해서 잠깐 메모장에 두세요.

⛔ 이 키는 어디에도 붙여넣지 마세요

화면 코드에도, AI 채팅에도, GitHub에도 넣으면 안 됩니다. 이 키 하나면 내 Notion 워크스페이스를 읽고 쓸 수 있어요. 나중에 Vercel 설정 화면에만 넣습니다. 실수로 어딘가에 올렸다면 통합 화면에서 키를 새로 발급받으세요(Rotate).

2단계 — 데이터베이스 만들고 링크 따기

  • 1

    새 페이지에 데이터베이스 만들기

    Notion에서 새 페이지를 만들고 본문에 /table을 쳐서 표 데이터베이스를 넣습니다. 그리고 1단계에서 정한 네 칸을 속성으로 만드세요.

    속성 이름속성 종류
    제목제목(Title) — 원래 있는 것
    작성자텍스트(Text)
    작성일날짜(Date)
    내용텍스트(Text)

    이름과 종류를 그대로 맞추세요. 스프레드시트 컬럼 순서와 같은 이야기입니다 — 코드가 이 이름으로 찾습니다.

  • 2

    통합을 이 페이지에 연결하기

    페이지 오른쪽 위 ··· → 연결(Connections) → 1단계에서 만든 통합 선택

  • 3

    주소에서 데이터베이스 ID 따기

    데이터베이스를 전체 페이지로 열고 주소창을 봅니다. 이렇게 생겼어요.

    notion.so/내워크스페이스/2a1b3c4d5e6f7890abcd1234ef567890?v=...

    가운데 영문·숫자 32자리가 데이터베이스 ID입니다. ?v= 앞까지만 복사해서 메모장에 두세요.

⚠ 2단계의 "연결"을 빠뜨리는 사람이 제일 많습니다

키를 제대로 만들어도 페이지에 통합을 연결하지 않으면 API가 그 페이지를 아예 못 봅니다. object_not_found라는 오류가 나는데, 키가 틀린 줄 알고 엉뚱한 데를 고치게 돼요. 안 될 때 여기부터 확인하세요.

＋ 받은 코드가 안 돌아가면 — 심부름꾼 예시 코드

저장소의 api/notion.js에 그대로 넣으면 됩니다. 속성 이름이 다르면 따옴표 안의 제목 · 작성자 · 작성일 · 내용만 자기 것으로 바꾸세요.

api/notion.js
const NOTION = 'https://api.notion.com/v1';
const DB = process.env.NOTION_DATABASE_ID;

const HEADERS = {
  'Authorization': 'Bearer ' + process.env.NOTION_TOKEN,
  'Notion-Version': '2022-06-28',
  'Content-Type': 'application/json'
};

/* 글자 속성에서 실제 텍스트만 꺼냅니다 */
function text(prop) {
  if (!prop) return '';
  const arr = prop.title || prop.rich_text || [];
  return arr.map(function (t) { return t.plain_text; }).join('');
}

export default async function handler(req, res) {
  try {
    if (req.method === 'GET') {
      const r = await fetch(NOTION + '/databases/' + DB + '/query', {
        method: 'POST',
        headers: HEADERS,
        body: JSON.stringify({
          sorts: [{ property: '작성일', direction: 'descending' }]
        })
      });
      const data = await r.json();
      if (!r.ok) throw new Error(data.message || '목록을 불러오지 못했습니다.');

      const posts = (data.results || []).map(function (p) {
        return {
          id: p.id,
          title: text(p.properties['제목']),
          author: text(p.properties['작성자']),
          date: (p.properties['작성일'] &&
                 p.properties['작성일'].date &&
                 p.properties['작성일'].date.start) || '',
          content: text(p.properties['내용'])
        };
      });
      return res.status(200).json({ ok: true, posts: posts });
    }

    if (req.method === 'POST') {
      const body = req.body || {};
      const today = new Date().toISOString().slice(0, 10);

      const r = await fetch(NOTION + '/pages', {
        method: 'POST',
        headers: HEADERS,
        body: JSON.stringify({
          parent: { database_id: DB },
          properties: {
            '제목':   { title:     [{ text: { content: body.title   || '' } }] },
            '작성자': { rich_text: [{ text: { content: body.author  || '' } }] },
            '작성일': { date: { start: today } },
            '내용':   { rich_text: [{ text: { content: body.content || '' } }] }
          }
        })
      });
      const data = await r.json();
      if (!r.ok) throw new Error(data.message || '저장하지 못했습니다.');
      return res.status(200).json({ ok: true });
    }

    return res.status(405).json({ ok: false, error: 'GET 아니면 POST만 됩니다.' });
  } catch (e) {
    return res.status(500).json({ ok: false, error: String(e.message || e) });
  }
}

⚠ 안 될 때 볼 순서
  • 목록이 비어 있다 — 2단계의 연결(Connections)을 했나요? 이게 제일 흔합니다
  • 500 오류 — Vercel 프로젝트의 Environment Variables에 두 값이 들어 있나요? 넣은 뒤 다시 배포했나요? 넣기만 하면 반영되지 않습니다
  • 속성을 못 찾는다는 오류 — Notion 속성 이름과 코드 속 이름이 한 글자라도 다르면 안 됩니다
  • Vercel 대시보드의 Logs에 서버 함수 오류가 그대로 찍힙니다. 브라우저 콘솔보다 여기가 정확해요

그 밖에 해볼 만한 것들

  • 검색창 추가 — 제목이나 작성자로 글을 찾는 입력칸. "목록 페이지 위에 검색창을 만들고, 입력한 단어가 제목이나 작성자에 포함된 글만 보이게 해줘."
  • 별점 매기기 — 시트에 "별점" 컬럼을 추가하고 글쓰기 폼에 ★ 1~5개 선택을 넣기.
  • 비밀번호로 글 삭제 — 글 쓸 때 네 자리 숫자를 같이 저장해두고, 그 숫자를 맞춰야 삭제되게 하기.
  • 색과 폰트 바꾸기 — 가장 만족도가 높은 작업입니다. "전체 색을 바다 느낌의 파란 계열로 바꿔줘" 한 줄이면 됩니다.

STEP 2 30분 AI 프롬프트

Google Sheets 연동

스프레드시트를 저장소로 씁니다

STEP 1에서 만든 화면은 새로고침하면 글이 사라집니다. 어디에도 적어두질 않았으니까요. 그 "어딘가"를 오늘은 Google 스프레드시트로 씁니다.

할 일코드를 두 번 나눠 받습니다 — ① 시트에 적어주는 Apps Script → 배포 → ② 그 주소를 부르는 화면 코드.
끝나면새로고침해도 글이 남습니다.
미리 알림오늘 중 가장 어려운 구간입니다. 절반쯤은 한 번 막혀요. 정상입니다.

구조는 단순합니다. 글을 쓰면 → 어떤 주소로 보내고 → 그 주소가 시트에 적어줍니다. 목록을 열 때는 반대로 받아옵니다.

심부름꾼 역할
이번에 새로 만듭니다

Google 스프레드시트에 딸려 있는 자동화 도구입니다. 엑셀의 매크로와 비슷하다고 생각하면 됩니다.

우리는 여기에 "누가 글을 보내오면 시트에 한 줄 적어줘"라는 코드를 넣고, 그걸 인터넷 주소 형태로 배포합니다. 그 주소가 위 그림의 ②, 화면과 시트를 잇는 다리예요.

즉 오늘의 백엔드는 이 둘입니다 — 심부름하는 Apps Script, 보관하는 스프레드시트.

1. 스프레드시트 준비하기

새 Google 스프레드시트를 만들고, 첫 번째 행에 STEP 1에서 고른 네 칸을 순서대로 입력합니다. 기본(책후기 게시판)이라면 이렇게요.

ABCD
제목작성자작성일내용

다른 주제를 골랐다면 그 네 칸을 쓰면 됩니다. 예를 들어 별점 랭킹이라면 가게 이름 · 추천인 · 별점 · 한줄평, 회비 장부라면 날짜 · 이름 · 항목 · 금액이 됩니다. 칸 개수와 순서만 STEP 1에서 만든 화면과 맞으면 됩니다.

⚠ 순서가 중요합니다

이 순서가 코드와 어긋나면 글은 저장되는데 화면에 엉뚱하게 나옵니다. 제목 자리에 작성자가 들어가는 식으로요. 원인을 찾기도 어려우니 지금 정확히 맞춰두세요.

2. Apps Script 코드를 AI에게 요청하기

코드는 두 뭉치가 필요합니다. 시트에 적어주는 Apps Script와, 그걸 부르는 화면 쪽 코드예요. 한 번에 다 받으면 길어져서 어긋나니 Apps Script부터 받습니다.

STEP 1을 진행했던 같은 대화창에 이어서 붙여넣으세요. 새 대화를 열면 AI가 앞에서 만든 화면을 모릅니다.

step2-appsscript.txt
방금 만든 웹사이트에 Google 스프레드시트를 저장소로 붙이려고 해.
먼저 Google Apps Script 코드만 만들어줘. 화면 쪽 코드는 나중에 부탁할게.

시트 첫 행은 [제목, 작성자, 작성일, 내용] 순서야.

이렇게 동작해야 해:
1. 목록을 불러오는 기능 (doGet) — 저장된 모든 줄을 JSON으로 돌려줘
2. 글을 저장하는 기능 (doPost) — 받은 값을 새 줄로 추가해줘
3. 작성일은 내가 보내지 않을 테니 저장할 때 오늘 날짜로 넣어줘

아래 세 가지는 꼭 지켜줘:
- 시트는 이름으로 찾지 말고 "첫 번째 시트"로 잡아줘.
  한국어 계정은 시트1, 영어 계정은 Sheet1이라 이름으로 찾으면 깨져.
- 화면에서 보낼 때 Content-Type을 text/plain으로 보낼 거야.
  그러니 e.postData.contents를 JSON.parse 해서 읽어줘.
- 응답은 ContentService로 JSON을 돌려줘.

[형식] 붙여넣기만 하면 되는 전체 코드로 주고,
각 함수가 무슨 일을 하는지 한 줄씩 설명해줘.
✱ 다른 주제를 골랐다면 한 줄만 바꾸세요

"시트 첫 행은 [제목, 작성자, 작성일, 내용] 순서야"를 내 네 칸으로 바꾸면 됩니다. 예를 들어 맛집 별점이라면 [가게 이름, 추천인, 별점, 한줄평]이에요. 나머지 문장은 주제와 상관없이 그대로 씁니다.

⚠ 아래 세 줄을 빼지 마세요

프롬프트에 붙인 "꼭 지켜줘" 세 가지는 실제로 자주 터지는 지점을 미리 막는 문장입니다. 빼고 요청하면 대개 이렇게 됩니다.

  • 시트 이름 — Sheet1로 찾는 코드가 와서 한국어 계정에서는 아무것도 안 나옵니다
  • text/plain — 저장할 때 CORS 오류가 납니다 (아래 접기 참고)
  • ContentService — 응답이 JSON이 아니라 화면에서 읽지 못합니다
＋ 왜 text/plain으로 보내나요 — 저장이 CORS 오류로 막히는 이유

브라우저는 Content-Type: application/json으로 보내는 요청을 "복잡한 요청"으로 보고, 본 요청 전에 허락을 구하는 요청(OPTIONS)을 먼저 보냅니다. 그런데 Apps Script 웹앱은 그 허락 요청에 답할 수 없어서 거기서 막힙니다. 화면에는 Failed to fetch나 CORS 오류로 보입니다.

text/plain으로 보내면 브라우저가 "단순한 요청"으로 취급해서 허락을 묻지 않고 바로 보냅니다. 내용은 어차피 글자라서, 받는 쪽에서 JSON.parse로 읽으면 똑같습니다.

인터넷 예제 중에는 mode: 'no-cors'를 쓰라는 것도 있는데 권하지 않습니다. 그렇게 하면 저장이 됐는지 실패했는지 화면에서 알 수가 없어서, 안 되는데 되는 줄 알고 넘어가게 됩니다.

＋ 받은 코드가 안 돌아가면 — 검증된 예시 코드

AI가 준 코드로 계속 막히면 아래를 그대로 쓰세요. 위 조건을 전부 지킨 코드입니다. 컬럼이 [제목, 작성자, 작성일, 내용] 기준이라, 다른 주제라면 title · author · content 이름만 자기 것으로 바꾸면 됩니다.

example-appsscript.js
/** 시트 첫 행: 제목 | 작성자 | 작성일 | 내용 */

function getSheet() {
  // 이름 대신 "첫 번째 시트"로 잡습니다.
  // 한국어 계정은 시트1, 영어 계정은 Sheet1이라 이름으로 찾으면 깨집니다.
  return SpreadsheetApp.getActiveSpreadsheet().getSheets()[0];
}

function json(obj) {
  return ContentService
    .createTextOutput(JSON.stringify(obj))
    .setMimeType(ContentService.MimeType.JSON);
}

/** 목록 불러오기 */
function doGet(e) {
  var rows = getSheet().getDataRange().getValues().slice(1); // 첫 행은 제목줄
  var posts = [];
  for (var i = 0; i < rows.length; i++) {
    if (!rows[i][0]) continue;            // 빈 줄 건너뛰기
    posts.push({
      id: i + 1,
      title: rows[i][0],
      author: rows[i][1],
      date: rows[i][2],
      content: rows[i][3]
    });
  }
  return json({ ok: true, posts: posts.reverse() });  // 최신 글이 위로
}

/** 글 저장하기 */
function doPost(e) {
  try {
    var data = JSON.parse(e.postData.contents);
    var today = Utilities.formatDate(
      new Date(), Session.getScriptTimeZone(), 'yyyy-MM-dd'
    );
    getSheet().appendRow([data.title, data.author, today, data.content]);
    return json({ ok: true });
  } catch (err) {
    return json({ ok: false, error: String(err) });
  }
}

이걸 썼다면 화면 쪽 코드도 여기에 맞춰야 합니다. 4단계의 예시 코드를 함께 쓰세요.

3. Apps Script에 코드 넣고 배포하기

  • 1

    Apps Script 편집기 열기

    스프레드시트 상단 메뉴에서 확장 프로그램 → Apps Script. 새 탭이 열리면 원래 적혀 있던 코드는 전부 지우고 AI가 준 Apps Script 코드를 붙여넣습니다.

  • 2

    웹앱으로 배포하기

    오른쪽 위 배포 → 새 배포 → 유형에서 웹 앱 선택. 설정 두 개가 핵심입니다.

    • 액세스 권한이 있는 사용자 — 모든 사용자
    • 다음 사용자로 실행 — 나
  • 3

    권한 승인 팝업 통과하기

    "이 앱은 Google에서 확인하지 않았습니다"라는 무서운 경고가 뜹니다. 내가 만든 스크립트이니 정상입니다. 고급 → (프로젝트 이름)(으)로 이동 → 허용 순서로 진행하세요.

  • 4

    웹앱 주소 복사해두기

    배포가 끝나면 https://script.google.com/macros/s/.../exec 형태의 주소가 나옵니다. 복사해서 메모장에 붙여두세요. 다음 단계에서 씁니다.

    /exec로 끝나야 합니다. /dev로 끝나는 주소는 나만 열 수 있어서 화면에서 부르면 실패합니다.

4. 화면 쪽 코드를 AI에게 요청하기

이제 두 번째 뭉치입니다. 웹앱 주소가 생긴 지금 요청해야 AI가 그 주소를 넣은 코드를 줍니다. 같은 대화창에 이어서 붙여넣으세요.

step2-frontend.txt
Apps Script 배포를 마쳤어. 내 웹앱 주소는 이거야:
(여기에 복사한 주소 붙여넣기)

이제 STEP 1에서 만든 화면 세 개가 이 주소를 쓰도록 고쳐줘.

1. 목록 페이지 — 열릴 때 주소에서 글을 불러와 카드로 보여줘
2. 글쓰기 페이지 — 등록을 누르면 주소로 보내고, 저장되면 목록으로 이동
3. 상세보기 페이지 — 목록에서 고른 글의 내용을 보여줘

저장할 때는 이렇게 보내줘:
- fetch의 headers를 Content-Type: text/plain 으로
- body는 JSON.stringify로 만든 글자

[형식] 고친 파일 전체 코드로 다시 줘.
파일마다 이름을 적어서, 어디에 붙여넣을지 알 수 있게 해줘.
＋ 2단계에서 예시 코드를 썼다면 — 짝이 되는 화면 코드

2단계의 검증된 Apps Script를 그대로 쓰셨다면, 화면 쪽은 아래 모양이 됩니다. AI가 준 코드가 안 돌아갈 때 이 세 조각만 비교해보세요.

example-frontend.js
// 세 파일 맨 위에 똑같이 넣습니다
const API = 'https://script.google.com/macros/s/여기에_내_주소/exec';

// [목록] 첫 화면(index.html) — 열릴 때 불러오기
fetch(API)
  .then(r => r.json())
  .then(d => {
    d.posts.forEach(p => {
      // p.id, p.title, p.author, p.date, p.content 로 카드를 그립니다
    });
  });

// [글쓰기] 입력 화면 — 등록 버튼
fetch(API, {
  method: 'POST',
  headers: { 'Content-Type': 'text/plain;charset=utf-8' },
  body: JSON.stringify({ title: 제목, author: 이름, content: 내용 })
})
  .then(r => r.json())
  .then(d => {
    if (d.ok) location.href = 'index.html';   // 목록으로 돌아가기
    else alert('저장 실패: ' + d.error);
  });

headers 줄이 application/json으로 되어 있으면 저장할 때 CORS 오류가 납니다. 2단계 접기에 이유를 적어뒀습니다.

5. 저장되는지 확인하기

글쓰기 화면에서 아무 글이나 등록한 뒤, 두 곳을 봅니다.

  • ✓

    스프레드시트에 행이 늘었나요?

    여기까지 되면 절반은 성공입니다. 보내는 길이 뚫렸다는 뜻이에요.

  • ✓

    목록 화면을 새로고침하면 그 글이 뜨나요?

    뜨면 완성입니다. 안 뜨면 받아오는 쪽 문제예요. 아래 경고부터 확인하세요.

⚠ 코드를 고친 뒤에는 매번 "새 배포"

Apps Script는 저장만으로는 반영되지 않습니다. 배포 → 배포 관리 → 수정(연필) → 버전: 새 버전 → 배포까지 해야 바뀐 코드가 적용돼요. "코드 고쳤는데 그대로예요"의 90%가 이 문제입니다.

⛔ 막혀도 괜찮습니다

여기서 절반 정도가 한 번쯤 막힙니다. 화면이 하얗게 뜨거나, 등록을 눌러도 반응이 없거나, 목록이 비어 있다면 에러 해결법을 여세요. 콘솔을 열고 빨간 글씨를 복사해서 AI에게 붙여넣는 것, 그게 전부입니다.

자주 나오는 질문

코드를 고쳤는데 화면이 그대로예요

열에 아홉은 재배포를 안 한 경우입니다. 바로 위 경고 상자의 순서대로 배포 관리 → 수정 → 새 버전 → 배포까지 해보세요.

글은 저장되는데 화면에 이상하게 나와요

시트 컬럼 순서와 코드가 어긋난 겁니다. 첫 행이 제목 · 작성자 · 작성일 · 내용 순서인지 확인하세요. 시트를 원래대로 돌리는 게 코드를 고치는 것보다 빠릅니다.

내 스프레드시트를 남들이 볼 수 있게 되나요?

시트 자체는 여전히 내 것입니다. 공개되는 건 웹앱 주소뿐이고, 그 주소는 우리가 코드에 적어둔 동작(글 추가·목록 읽기)만 합니다. 다만 주소를 아는 사람은 글을 남길 수 있으니 아무 데나 공유하진 마세요.

"모든 사용자"로 열어두는 게 위험하지 않나요?

오늘 만드는 동네 게시판 수준에서는 괜찮습니다. 여기서 "모든 사용자"는 시트 전체가 아니라 그 웹앱 주소로 들어온 요청을 처리하겠다는 뜻이에요. 비밀번호나 개인정보를 다룬다면 이야기가 달라집니다.

여러 명이 같은 시트를 써도 되나요?

됩니다. 막힌 사람이 많을 때 진행자 시트를 함께 쓰기도 해요. 나중에 자기 시트로 바꾸려면 코드 안의 웹앱 주소만 교체하면 됩니다.

🎤 진행자용 — 이 구간 운영 방법
  • 1단계 시트 준비는 다 함께. 주제가 달라도 "네 칸을 만든다"는 동작은 같습니다. 화면 공유로 한 번 같이 만들되, 각자 자기 칸 이름을 넣게 하세요. 한 명이라도 순서가 틀리면 나중에 원인 찾기가 아주 어렵습니다.
  • 주제를 바꾼 사람은 2단계 프롬프트의 컬럼 줄을 자기 네 칸으로 고쳤는지 확인해 주세요. 여기서 안 고치면 시트와 코드가 어긋납니다.
  • 3단계 배포는 진행자가 시연 먼저. 특히 "확인되지 않은 앱" 경고 화면을 미리 보여주고 넘어가야 당황하지 않습니다.
  • AI가 준 코드로 10분 넘게 막히면 접기 상자의 예시 코드로 넘기세요. 2단계(Apps Script)와 4단계(화면)의 예시는 짝이라 둘 다 함께 써야 합니다. 오늘 목표는 코드를 직접 뽑는 게 아니라 연동되는 화면을 보는 것입니다.
  • 진도를 맞추려 하지 마세요. 먼저 된 사람이 옆 사람을 돕게 하면, 6명 중 2~3명만 통과해도 나머지가 금방 따라옵니다.
  • 20분이 지나도 절반 이상 막혀 있으면 진행자의 웹앱 주소를 공유해 다 같이 같은 시트를 쓰게 하세요. 각자 저장은 못 해도 연동되는 화면은 다 같이 볼 수 있습니다.
  • 30분이 넘으면 과감히 넘기세요. 여기서 시간을 다 쓰면 STEP 3 배포가 잘리고, 그러면 오늘의 하이라이트가 사라집니다.
